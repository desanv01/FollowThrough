# DeepSeek Chat Completions adapter

`adapters.deepseek.DeepSeekClient(api_key, transport=...)` is a one-request protocol client. Call `complete(messages, tools=None, max_cost_usd="0.01", max_tokens=64)` with an explicit budget. The result exposes the requested alias, returned model string, assistant message, parsed function calls, usage and reservation. The official default transport uses verified TLS to `https://api.deepseek.com/chat/completions` and sends `deepseek-flash` with thinking enabled and effort set to high. A returned model string is a reported identity. The requested alias does not pin a snapshot.

For a tool turn, execute approved tools in the caller and pass `{tool_call_id: string_result}` to `append_tool_results(messages, completion.assistant_message, results)`. It adds the exact returned assistant fields and one tool result per ID in provider order. Invalid function arguments yield `ToolCall.arguments_error == "invalid_tool_arguments"` so a caller can return a tool error and replay the original arguments. The caller must source assistant tool turns from the provider. The helper validates shape and matching IDs. It has no provenance or tool execution capability.

An injected transport implements `transport(body: bytes, api_key: str, *, timeout_seconds: int, max_response_bytes: int) -> HttpResponse`. The callable receives a credential and must be trusted. It must enforce the passed time limit and send at most once. The client validates its response size and shape. The default does not use redirects or proxies. It bounds caller wait and requests socket shutdown at the deadline. Local DNS or connection cleanup can settle after the deadline. After dispatch, treat timeout and unusable responses as uncertain and retain the reservation. Never automatically retry.

`DeepSeekError.code` is stable diagnostic data, with `status` for HTTP errors, `reservation_usd` when computed and `outcome_unknown` for uncertain or unusable results. Even a known HTTP status supplies no charge reconciliation. `Usage.raw` and `DeepSeekError.raw_usage` hold raw provider usage when a parsed response exposes it. Keep raw provider fields and assistant reasoning restricted. Successful usage separates cached and uncached input and counts reasoning inside output. Normalized fields stay `None` when missing and underdetermined. The estimated usage cost stays `None` if any billing bucket is undetermined.

## Reservation assumptions

Request JSON is limited to 65,536 bytes, output to 4,096 requested tokens, the response body to 131,072 bytes, and timeout to 30 seconds. The defaults are 64 output tokens and 15 seconds. Before dispatch the client reserves twice the serialized request byte count plus 4,096 tokens at the peak uncached input rate, and the full `max_tokens` at the peak output rate. This local envelope assumes the provider's tokenization and server-inserted prompt fit the input allowance, `max_tokens` caps all billed output including reasoning, and the configured rates bound the returned model's charges. Observed usage outside that envelope is a protocol error. The reservation is conditional on those assumptions and does not guarantee billing. Reconfirm the rates and token semantics before a paid campaign. The caller owns any aggregate budget and charge reconciliation.

## Readiness command

The entry point requires the exact `--live` flag, a finite positive `--max-cost-usd` that covers the local reservation, and `DEEPSEEK_API_KEY` from the process environment. It sends a fixed single-turn readiness request and emits only model and reservation metadata. Run it only under a separate authorized paid operation. The offline test command is `python -B -m unittest discover -s tests -p test_deepseek_adapter.py -v` from the project root. The tests use injected transports and mocked HTTPS connections and credentials.
