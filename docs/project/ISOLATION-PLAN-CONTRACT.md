# Rust container plan contract v0.1

P2-ISOLATION-PLAN/r1 implements a typed, validated Docker command plan in the existing Rust crate. It does not execute Docker, containers, shell commands or model code. This is the ready source-preparation portion of P2.3; actual lifecycle control, negative isolation qualification and protected grading remain separate prerequisites.

New proposed files only: runner/src/isolation_plan.rs, runner/src/bin/isolation-plan.rs, runner/tests/isolation_plan.rs, docs/project/ISOLATION-PLAN.md. Existing Cargo.toml/Cargo.lock/dependencies/main.rs/paths.rs/process.rs remain unchanged. The binary can use a path module for isolation_plan.rs without changing the existing controller. Existing serde/serde_json/sha2 plus Rust std only. No new crates or lock edits.

CLI: `cargo run --offline --locked --manifest-path runner/Cargo.toml --bin isolation-plan -- --workspace <existing-flat-directory> --run-id <id> --output <new-json-file>`. Module exports a typed build_plan(workspace, run_id) result with no I/O mutation; reading/hashing input files is allowed. CLI writes exactly one new plan with exclusive create, does not overwrite output and never launches the plan. Output must be outside workspace. On validation/write failure return nonzero with fixed/sanitized diagnostics, not an execution receipt.

Validate run ID 1..48 ASCII alphanumeric/_/-; container name ft-check-<run_id>. Workspace must be an explicit existing directory with no symlink/reparse component and a flat allowlisted inventory. Required exactly one candidate processor.py or preview.py, plus public_checks.py. Optional TASK.md, SPEC.md, WORKFLOW.md, HISTORY.json. Reject other names, directories, symlink/reparse files, both candidates, missing files, nonregular files, unrepresentable paths and Docker --mount delimiter injection (comma, CR/LF/NUL; do not reject ordinary Windows drive colon or spaces). Per-file <=1 MiB, total <=2 MiB; bounded reads and actual SHA256/byte counts. No root project, grader, reference, .env, socket or controller mount can fit this allowlist. This assumes a stable host workspace; a plan alone does not prevent subsequent replacement/TOCTOU.

Fixed image: python@sha256:d29f48a31a8b408ed19272ca1e7b10ebae13b240a27e862d3d4217c528e2e0c3 (previously inspected local Python3.11.15 image; availability must be rechecked by later execution owner). No tag fallback or image pull.

Produce schema_version0.1, kind agent_check_plan, evidence_kind execution_plan_not_run, run_id/container_name/image, canonical workspace and its inventory, resource limits, and argv as a JSON array. Program docker; argv begins run and fixes:
--pull=never, --rm, --name <owned-name>, --label org.followthrough.run_id=<run_id>, --network=none, --read-only, --cap-drop=ALL, --security-opt=no-new-privileges, --pids-limit=64, --memory=256m, --cpus=1, --user=65534:65534, --tmpfs /tmp:rw,noexec,nosuid,size=16m, --workdir=/workspace, --mount type=bind,src=<canonical-workspace>,dst=/workspace,readonly, --entrypoint=python, immutable image, then -I -B /workspace/public_checks.py.

No additional caller-provided executable/argv/env/mount/network/image overrides. No shell-string construction, docker socket, privilege, host namespace or credential forwarding. Workspace is read-only during a check; later host tools edit only the candidate between checks. stdout/stderr limits32KiB each, runtime60s and cleanup deadline5s are declared policy fields, NOT enforced claims at this stage. Do not emit success/grade/PID/exit or any live observation. CLI no-op run cannot establish isolation.

Document the later executor obligations: verify unchanged inventory, qualify installed image and exact owned container identity, bound streams/time, cancel and remove only the owned container, join CLI subprocess, record unknown cleanup, keep host receipts outside mounts, and separate hidden grading. Existing process.rs direct-child cleanup is insufficient to claim container cleanup; do not silently reuse that claim. Grader protection is not implemented by this plan.

Tests use owned host scratch under the candidate overlay only. Exercise valid retry/cache inventory and stable hashes; space-bearing paths; invalid paths/IDs/extra files/size/symlink-or-reparse rejection where supported with honest skips; exclusive output and external-cwd CLI; exact flags and absence of overrides; proof CLI did not invoke Docker (fake executable sentinel or equivalent). Candidate code is never executed by this packet. Set CARGO_TARGET_DIR to owned overlay/tmp/build; use offline locked Cargo and existing caches. No Docker/shared runtime ownership is needed because no containers run. Deliver source-only preparation, not sandbox qualification.
