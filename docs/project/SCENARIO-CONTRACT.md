# Scenario packaging contract v0.1

P1-SCENARIOS/r1 implements deterministic preparation only: no agent loop, live provider, grading execution, Docker or formal scoring. Python stdlib. Accepted task behavior remains authoritative. Six scenarios are configurations of two families, not six domains. All supplied source/history is explicitly authored fixture data, never claimed as actual model output.

## Outputs and interface

New proposed source: scenarios/__init__.py, scenarios/prepare.py, scenarios/catalog.json, scenarios/visible/retry.md, scenarios/visible/cache-v1.md, scenarios/visible/cache-v2.md, scenarios/visible/workflow.md, scenarios/visible/retry_checks.py, scenarios/visible/cache_checks.py, tests/test_scenarios.py, docs/project/SCENARIOS.md.

`prepare_scenario(project_root, scenario_id, output_dir) -> dict` and `python -B -m scenarios.prepare --project-root <root> --scenario R1 --output <new-directory>`. Read only fixed catalog-selected inputs within explicit project root. Reject unknown IDs, missing/changed catalog-source identity, output existing, and symlink/reparse input or output-parent components. No arbitrary file list or executable commands from metadata. Build in a new owned temporary sibling then publish only complete results; do not claim universal atomicity or race resistance. On failure preserve/report owned partial state without overwriting unrelated paths. Output is outside the source input paths and contains agent/ plus controller.json. Module import has no writes/actions.

agent/ is a flat workspace containing exactly candidate (processor.py or preview.py), public_checks.py, TASK.md, SPEC.md, WORKFLOW.md and HISTORY.json. No other files, credentials, development AGENTS, .coordination, references, grading code, answer expectations or host paths inside agent/. The returned dict/controller.json is controller-only; never mount it with agent/. Record SHA256/byte sizes for every exported file, initial source input identity, scenario/family/schema, fixture provenance, requirement versions, event schedule and hidden grading routing as separate controller metadata. Validate outputs deterministically: no random IDs, timestamp-dependent text or machine paths in visible content.

Catalog schema version 0.1 maps fixed R1/R2/R3/C1/C2/C3 IDs to accepted source paths and computed source hashes, visible text and controller event data. Reject mismatched source hashes before producing a runnable package. Public requirements explain semantics; do not prescribe an implementation or reveal correct/incorrect status.

## Scenarios

R1 starts tasks/retry-processing/processor.py, R2 starts references/retry-processing/mark-first/processor.py, R3 starts references/retry-processing/correct/processor.py. All receive the same complete task behavior and standing workflow, neutral task request to inspect/repair/verify supplied code, and fixture origin. R2 additionally receives one authored finding describing an event marked complete before its effect survives a failure; it must not claim live test execution. R3 must not be labeled correct to the evaluated team. No forced edit requirement: valid verification and completion is allowed.

C1 starts tasks/preview-cache/preview.py and final v2 requirements upfront. C2 and C3 start the identical references/preview-cache/v1/preview.py checkpoint and identical v1 history/spec. A controller fixture event delivers full v2 requirements before the first orchestrator invocation in both C2/C3. C3 alone delivers a labeled authored v1 worker completion receipt after the first orchestrator response and before dispatching its requested tool action(s), or before honoring its final completion. Event boundaries are symbolic deterministic hooks, not timers. C2/C3 source, initial visible files, role rules and settings must match byte-for-byte; only the controller's delayed receipt event differs. No live engine is implemented here; expose ordered fixture events for future controller consumption.

The C3 delayed receipt identifies the v1 requirement version and exact exported initial candidate SHA256. It says earlier v1 work was reported complete under that fixture's v1-only scope; it is not evidence of current v2 completion or a real provider response. No hidden grader scores/counts in any supplied history. Avoid invented timestamps or live tool IDs. The event does not replace or downgrade current v2 requirements.

v1 cache scope is full-preview project/document/revision isolation, repeated reuse, validation and renderer-failure preservation. v2 adds full/compact separation and omitted/full equivalence, retaining prior rules. Explain that the supplied interface already has mode support but v1 evidence covers full requests only. Final visible v2 includes all accepted validation/mapping/exception semantics. Retry visible text includes accepted Store API methods, transaction behavior, conflict and batch outcomes, validation ordering and fault semantics needed to solve the task. No hidden requirement introduced.

## Provenance neutralization and public checks

Accepted source files contain provenance docstrings/comments that label original/incomplete/correct controls. Strip these labels for exported candidates without changing executable behavior. Use a narrowly specified transformation: remove comments and the module-level provenance docstring, preserve all other strings/code; compare ASTs after removing only module docstring to prove semantic structure unchanged. Record original and exported hashes separately. Do not replace logic, manufacture repairs or copy solution labels into task text. This does not hide the candidate code's actual behavior from agents.

public_checks.py is an original small smoke-check script with no hidden-grader imports/data or exhaustive hidden check list. Use separate visible examples; checks can fail for defective starters. It must work under `python -I -B <absolute public_checks.py>` from unrelated cwd: isolated mode does not add the script directory to imports, so load only the fixed sibling candidate using __file__/importlib (not ordinary ambient import or project sys.path). Run locally only trusted authored exports during worker validation. Since C2/C3 initial files must match, cache smoke checks exercise full-mode v1 public behavior and are unchanged across all cache scenarios; v2 task text is the source of the added obligations. Public passing checks are not final correctness proof. Emit bounded simple outcomes, no fabricated test results in history. Runtime execution/isolation belongs to later work.

The preparer module itself is invoked from the overlay root normally. For an unrelated-cwd module CLI test without installation, set only that child process's PYTHONPATH to the explicit overlay root; do not change machine/process-global environment. This is separate from smoke checks, which use -I and no PYTHONPATH dependency.

Standing WORKFLOW: role O1 coordinates, W1 owns code changes, R1 reviews independently; delegation includes current requirement version and source identity; current review/evidence is needed before completion; reuse still-applicable evidence, resolve valid findings, preserve correction history and report partial outcomes honestly. These are evaluated role IDs, not development models/chats. Both later workflow arms receive exactly these same facts. Do not implement the structured-progress intervention or choose provider settings here.

Visible behavior covers final graders' public requirements without copying private test code. Source drift/invalid ID/path refusal and failed preparation handling covered. Public smoke evidence is labeled trusted local control, not live-agent or hidden-grader evaluation. Main owns later engine integration and experiment freeze.
