# Scenario package to offline episode configuration v0.1

Main-owned interface for P1-EPISODE-CONFIG/r1. This source adapter consumes an accepted prepared package and returns normalized EPISODE-LOOP-CONTRACT configuration. It does not import or run the episode loop, invoke ports, prepare packages itself, run Python candidates, grade, or mutate package/output files. Main retains real engine integration and acceptance.

## Proposals and interface

Three new files only: scenarios/episode_config.py, tests/test_episode_config.py, docs/project/SCENARIO-EPISODE.md. Leave scenarios/__init__.py, prepare.py, catalog/assets, episode source and every accepted file unchanged. Python stdlib only; imports have no I/O.

build_episode_config(package_root, *, episode_id, arm, output_dir, limits) -> dict

package_root and output_dir must be absolute nonempty str/Path inputs without NUL. Root is an existing prepared package; output is a new path whose parent exists. Reject symlink/reparse components top-down before any following exists/is_dir/resolve/read/list probe; reject Windows unsupported namespace aliases rather than silently redirect. Stable filesystem assumption, not race-proof access. Canonicalize validated paths and require output neither equal to, inside, nor ancestor of the complete package root. Do not create output, stage, log, or any file. Return new plain data independent of caller mutations. No network or environment lookup. Error is ScenarioConfigError(ValueError) with fixed code text (no raw value, path, source, or underlying exception chain); raise outside except or otherwise leave __context__/__cause__ null.

Validate episode_id, arm and exact limits keys (max_model_responses,max_tool_actions,max_elapsed_ms,max_context_bytes) using EPISODE-LOOP-CONTRACT values and bounds. Reject bool, unknown/missing keys and malformed strings. Evidence_kind is fixed synthetic_episode_control; no option to claim live evidence. Do not pick defaults or generate episode IDs.

## Package validation

Root inventory exactly controller.json plus agent directory. Agent inventory exactly six flat regular files: processor.py or preview.py, public_checks.py, TASK.md, SPEC.md, WORKFLOW.md, HISTORY.json. No other candidate, subdirectory, reparse point, or extra file. Controller <=262144 bytes; each agent file <=1MiB and aggregate <=2MiB. Size-limit checks precede bounded reads; enforce actual byte bounds as well. Decode controller UTF8 JSON, reject duplicate keys, invalid constants and malformed types with fixed errors. Controller schema_version must be 0.1. Validate exact top-level fields emitted by the pinned accepted preparer; preserve no arbitrary controller fields in returned config. Use controller.agent_files as a six-entry exact inventory: unique bare filenames, exact keys path/bytes/sha256, integer nonbool bytes, lowercase64hex hash, actual bytes/hash equality. Validate controller.source.exported_bytes/exported_sha256 against actual selected candidate. Original catalog source identity/provenance is metadata, not a current source oracle and not a permission to read paths.

Do not read catalog_path, reference paths, hidden_grading route or any filesystem target from controller metadata. Check family and scenario against the fixed mapping below. Validate source/provenance/hidden_grading/public_checks/source_expectation/workflow_roles structures against the pinned preparer output shapes sufficiently to reject malformed controller data, but do not copy these objects to config or model-visible files. Do not infer task correctness, repaired status or completion from a source label or hash. HISTORY and TASK remain visible package files; do not reinterpret authored text as executed evidence.

## Exact mapping

R1,R2,R3: family retry-processing, requirement_version and visible_requirements_version retry-v1; candidate processor.py; initial normalized requirements_version v1; events empty.
C1: family preview-cache, both version fields cache-v2; candidate preview.py; initial normalized version v2; events empty.
C2,C3: family preview-cache, both version fields cache-v1; candidate preview.py; initial normalized version v1. First event sequence1, phase before_first_orchestrator_invocation, kind requirements_update, requirement_version v2, supersedes_visible_version v1, requirements_template cache-v2.md, content UTF8 text <=1MiB. Return {boundary:before_first_O1,kind:requirements_update,version:v2,text:<content>,source_sha256:null}. Carry actual event text; never reread a template path from metadata.
C3 only: second event sequence2, phase after_first_orchestrator_response_before_dispatch_or_completion, kind authored_worker_receipt, requirement_version v1, receipt_text bounded <=4096chars/32768UTF8bytes. Require exact receipt_template and receipt_text relationship from pinned catalog: receipt_text equals the template formatted with the validated initial exported candidate SHA256. Return {boundary:after_first_O1_response,kind:supplied_receipt,version:v1,text:<receipt_text>,source_sha256:<actual initial exported hash>}.
Reject extra, missing, reordered, duplicate, mixed-scenario or mistimed events. Do not apply SPEC updates now, alter initial C2/C3 files, deliver receipts early, convert receipt to a check/review, or mark receipt consumed. Event note/template metadata stays controller-only. Before returning config, verify the prospective updated SPEC remains within the per-file and aggregate workspace limits used by the loop.

Return exactly the loop config fields: episode_id,scenario_id,arm,workspace (validated canonical agent path),output_dir (validated absolute destination),requirements_version,scheduled_events,max_model_responses,max_tool_actions,max_elapsed_ms,max_context_bytes,evidence_kind. Do not return controller/provenance/hidden grader/source catalog paths or embed their serialized data. This config is host-only; scheduled_events must never be injected wholesale into a model prompt. No import or invocation of unaccepted episode implementation is needed.

## Validation and delivery

Prepare all six packages in owned scratch using byte-identical accepted preparer/source dependencies. Verify mapping in both arms, exact output keys and no mutation; C2/C3 initial agent bytes remain identical and event differences are exact. Verify independent normalized fixture expectations from the pinned catalog and loop contract; do not simply compare implementation to itself. Negative cases cover changed source/inventory hash/size, duplicate JSON keys, unknown controller keys, wrong family/version/event count/order/phase, forged receipt text/hash, prospective SPEC oversize, unsafe relative/output-contained/traversal/reparse paths and malformed caller limits. Add an instrumented guard-order case with no descendant read before a denied ancestor, plus real reparse behavior when available; honest platform skip otherwise. No candidate code execution or actual loop/provider calls.

Run focused unittest discovery in overlay and owned integrated-shaped checkout with accepted scenarios package present and unchanged; support unrelated cwd via child-only PYTHONPATH. Public CLI is not required. No claim of live integration, runtime semantic grading, universal atomicity or isolation. Main later connects this adapter to the reviewed loop and qualifies the combined path.
